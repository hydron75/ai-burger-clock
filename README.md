# AI Burger Clock 2.3.0 — Windows 배포 준비

**Windows 2.3.0 후보를 2026-10-09 KST에 준비했습니다. 아직 병합·배포하지 않았으며 로컬 배포 EXE는 2.2.4(main `670f45a`) 그대로입니다. 교체는 사용자 승인 뒤 진행합니다.**

**“지금 이 AI로 큰 작업을 시작해도 괜찮을까?”를 살펴보는 작은 Windows 신호등입니다.**

작업표시줄 오른쪽, 시계 근처에 머무릅니다. 아이콘을 누르면 시간표와 ChatGPT·Claude·Gemini의 공식 상태를 볼 수 있습니다.

이 앱이 AI를 빠르게 만들어 주거나 작업을 대신 실행하는 것은 아닙니다. **시작할 때 참고할 정보를 모아 보여주는 도구**입니다.

## 1. 다섯 가지 정보를 따로 봅니다

| 정보 | 쉽게 말하면 | 어디에서 오나요? |
|---|---|---|
| Schedule | “미국에서 보통 일하는 시간인가?”라는 시간표 | 미국 시각과 공휴일 규칙 |
| Official | “서비스에 문제가 있다고 공지했나?”라는 공식 게시판 | 각 회사의 상태 페이지 |
| 작업 권고 | “지금 새 대형 작업을 시작할까?”라는 안내 | 시간표 + 공식 게시판 |
| 사용 경험 | “내가 써 보니 어땠나?”라는 개인 수첩 | 사용자가 직접 누른 기록 |
| 계정 한도 | “내가 이 계정으로 얼마나 더 쓸 수 있나?”라는 잔여량 | 로그인된 공식 Codex·Claude·agy CLI (agy는 2.3.0 후보) |

예를 들어 시간표는 FULL THROTTLE이어도, OpenAI가 관련 장애를 공지하면 ChatGPT에는 STOP을 표시합니다. Claude와 Gemini가 정상이면 두 서비스는 GO로 남습니다.

반대로 공식 상태가 정상이라고 해서 BURGER TIME을 FULL THROTTLE로 바꾸지는 않습니다.

**시간표도, 공식 정상 표시도 실제 속도나 성공을 보장하지 않습니다.** 그래서 내 사용 경험을 별도로 기록합니다.

## 2. 처음 실행하기

1. Windows 11 x64 PC에서 사용합니다.
2. **.NET 10 Desktop Runtime x64**가 필요합니다. 앱을 실행하는 데 필요한 공용 부품이라고 생각하면 됩니다. 직접 코드를 빌드하지 않는다면 Visual Studio나 SDK는 필요하지 않습니다.
3. 배포 폴더의 실행 파일을 엽니다.

~~~text
dist\win-x64\AI Burger Clock.exe
~~~

별도 설치 프로그램은 없습니다. 시간표·공식 상태·기록에는 SQLite 서버, API 키, AI 계정 로그인이 필요하지 않습니다. **계정 한도만** 해당 PC에 설치하고 로그인해 둔 공식 Codex·Claude CLI가 필요합니다. 2.3.0 후보의 Gemini 한도에는 공식 agy CLI가 필요합니다. 앱이 CLI를 설치하거나 로그인 창을 대신 띄우지는 않습니다. DB용 부품은 EXE에 들어 있으며 필요한 네이티브 파일은 실행할 때 임시 위치에 풀립니다.

아이콘이 안 보이면 시계 옆의 숨겨진 아이콘 목록도 확인하세요. 이미 실행 중일 때 한 번 더 실행해도 새 인스턴스는 만들지 않습니다.

Provider는 여기서 **ChatGPT·Claude·Gemini 같은 서비스 구분**을 뜻합니다. 2.2.3부터 OpenAI의 화면 표시 이름을 ChatGPT로 맞췄습니다. 공식 상태 주소와 내부 식별자·DB의 `OpenAI` 저장값은 그대로입니다.

사용 경험 기록·설정·통계는 트레이 우클릭 메뉴에서도 이용할 수 있습니다. 상태 창의 X를 누르거나 다른 창으로 이동하면 작은 창만 숨겨지고, 앱은 트레이에 남습니다.

공식 페이지는 Windows 기본 브라우저로 열립니다. 미리 정해 둔 공식 주소만 사용하며, 가져온 공지 속 임의의 링크를 실행하지 않습니다.

### 계정 한도는 어떻게 보나요?

**2.3.0 후보**에서는 ‘한도 보기’를 누르면 같은 작은 창 안에서 **ChatGPT·Claude·Gemini**의 잔여율, 리셋까지 남은 시간, 마지막 성공·다음 조회 시각을 보여줍니다. ChatGPT 제목 아래의 **Work/Codex**와 Gemini 아래의 **Antigravity · Gemini 모델**은 실제 조회 범위이며, 일반 ChatGPT나 Gemini Apps의 모든 한도를 뜻하지 않습니다. 글자 위에 마우스를 올리면 정확한 KST 리셋 시각과 실패 이유를 볼 수 있습니다. 현재 배포 **2.2.4에는 ChatGPT와 Claude 한도만** 있으며 Gemini 서비스 상태·기록·통계는 기존에도 있습니다.

2.2.4부터 사용하는 **Provider별 흰 박스** 모양을 유지하고 Gemini 박스를 추가합니다. 제목은 박스 밖 상태 화면과 같은 기준선에 두고, 박스 안 글자는 상태 카드와 같은 위치에서 시작합니다. 한도 박스에는 hover 효과가 없으며 ‘한도 보기 ↔ 상태 보기’ 전환과 창 크기(논리 374×518)는 유지합니다. 2.3.0 후보는 세 Provider가 늘어난 만큼 한도 영역 안에서 세로로 스크롤합니다. 창 전체나 가로 스크롤은 아닙니다.

- `잔여 55%`는 공식 응답의 사용률이 45%라는 뜻입니다. 응답에 있는 창만 표시하므로 주간 한도만 나올 수도 있습니다.
- 기본 **6시간**, 어느 창이든 잔여 **0% 초과~10% 미만이면 1시간**, **정확히 0%이면 15분**, 알려진 리셋 **15분 전~15분 후에는 5분**마다 확인합니다. Provider별로 가장 짧은 주기를 적용합니다. 화면에서 반올림된 글자가 아니라 원본 수치로 판정하며, 새 조회에서 회복되면 그 잔여량에 맞는 주기로 돌아갑니다.
- 한도 조회가 실패하면 **15분 → 30분 → 1시간…** 간격으로 재시도하되 평소 주기를 넘지 않습니다. 마지막 확인값이 0%라면 실패가 이어져도 15분을 넘지 않습니다. 리셋 구간의 더 빠른 조회가 우선이고, 성공하면 실패 횟수를 초기화합니다.
- 앱 시작·절전 복귀 때 바로 확인합니다. 연결 복구는 네트워크 변화 뒤 **5초** 기다렸다가 공식 상태와 계정 한도를 함께 확인합니다. 기다리는 중 다시 바뀌면 마지막 변화부터 5초를 기다리고, 직전 연결 복구 조회 후 1분 이내의 변화는 버리지 않고 1분 시점으로 미룹니다. 대기 끝에 사용 가능한 연결이 없으면 해당 조회를 건너뛰며 1분 제한도 쓰지 않습니다. 이 판정은 인터넷·DNS 접속 성공까지 보장하지 않습니다. 카운트다운 자체는 인터넷을 사용하지 않습니다.
- 기존 Refresh와 트레이의 **‘상태·한도 새로 고침’**은 세 Provider 한도와 공식 상태를 함께 갱신합니다(배포 2.2.4는 두 한도). 한도 조회 중에도 공식 상태를 새로 고칠 수 있으며, 이미 조회 중인 한도는 중복 실행하지 않습니다. 공식 상태 자체가 조회 중일 때는 Refresh 버튼이 잠시 비활성화됩니다.
- 조회 실패는 ‘조회 불가’ 또는 ‘이전 조회값’입니다. 리셋 예정 시각이 지나도 임의로 100%로 바꾸지 않고 ‘갱신 대기’로 표시합니다. 성공 시각은 CLI 응답을 받은 시각이지 서버 데이터 생성 시각을 보장하지 않습니다.
- 인증은 각 공식 CLI가 관리합니다. 이 앱은 인증 파일·쿠키를 직접 읽거나 비공개 HTTP API를 호출하지 않습니다. Claude는 모델 턴·토큰·보고 비용 0인 `/usage` 결과만 받습니다.

한도 부족을 서비스 장애로 표시하거나 트레이 색상·시간표·실측 통계를 바꾸지 않습니다. 크레딧 처리, 리셋권 조회·사용, 한도 리셋 알림, 자동 작업 실행, 일반 ChatGPT 모델별 메시지 한도는 포함하지 않습니다. Claude의 실험적 응답이 누락될 수 있는 제한과 실제 확인 결과는 [상세 기록](ACCOUNT_QUOTAS.md)을 참고하세요.

### 2.3.0 후보의 Gemini 한도 (미배포)

- `Gemini` 제목 아래 **Antigravity · Gemini 모델** 범위를 표시합니다. `Gemini Models` 그룹의 5시간·주간 잔여율과 리셋 시각만 읽으며 Gemini Apps, Claude/GPT 모델 그룹, 크레딧은 포함하지 않습니다.

## 4. F/B와 색상은 서로 다른 뜻입니다

**문자는 시간표, 색상은 주의할 정도**입니다.

- **F:** FULL THROTTLE. 미국 업무시간을 피한 구간입니다.
- **B:** BURGER TIME. 미국 업무시간과 겹치는 구간입니다.

색상은 다음 순서로 결정합니다. 위쪽 조건이 있으면 아래쪽보다 우선합니다.

| 색상 | 뜻 |
|---|---|
| 빨강 | 하나 이상의 Provider에 일부 또는 주요 장애가 확인됨 |
| 주황 | 위 장애 없이 성능 저하가 있음. 또는 모두 정상이지만 BURGER TIME임 |
| 회색 | 확인된 장애·성능 저하는 없지만, UNKNOWN/STALE가 있는 Provider가 있음 |
| 초록 | FULL THROTTLE이고 모든 Provider가 공식 정상임 |

예: **주황색 F**는 “시간표는 좋지만, 확인된 서비스 문제가 있다”는 뜻입니다.

마우스를 아이콘 위에 올리면 다음 전환까지 남은 시간과 세 Provider의 개별 권고가 나옵니다. **빨간 아이콘 하나가 세 서비스 모두의 장애를 뜻하지는 않습니다.**

## 5. GO, HOLD, STOP, CHECK는 무엇인가요?

| 시간표 | 해당 Provider의 공식 상태 | 앱의 권고 |
|---|---|---|
| FULL | 정상 | GO — 새 대형 작업을 시작할 후보 시간 |
| FULL | 성능 저하 | HOLD — 새 대형 작업은 잠시 미루기 |
| FULL | 일부·주요 장애 | STOP — 해당 Provider에서 새 대형 작업 시작을 피하기 |
| FULL | 확인 불가·오래된 정보 | CHECK — 공식 상태를 직접 확인하기 |
| BURGER | 정상 | BURGER TIME 유지 |
| BURGER | 성능 저하·장애 | BURGER + ISSUE — 시간표와 서비스 모두 주의 |
| BURGER | 확인 불가·오래된 정보 | BURGER + CHECK — 시간표 주의, 공식 상태 확인 필요 |

STOP은 **권고 문구**입니다. 앱이 다른 AI 프로그램을 강제로 막거나, 이미 실행 중인 작업을 종료하지는 않습니다.

공식 상태는 보통 5분 간격으로 확인합니다.

- **UNKNOWN:** 아직 확인하지 못했거나, 응답을 제대로 해석하지 못했습니다.
- **STALE:** 마지막으로 상태 확인에 성공한 뒤 15분 이상 지났습니다. “장애 확정”이 아니라 “새 정보가 필요함”입니다.

‘최근 조회 시도’는 성공 시각과 다릅니다. Provider 상태 글자 위에 마우스를 올리면 마지막 성공 시각과 실패 이유를 따로 볼 수 있습니다.

2.2.4의 상세 도움말은 값이 없는 관련 구성요소·사건·사건 ID·마지막 알려진 상태·출처 줄을 숨깁니다. 최근 조회·성공 시각은 유지하며, 트레이 카운트다운도 기존 초 단위입니다.

## 6. 왜 어떤 날은 22시, 어떤 날은 23시인가요?

한국의 10시·22시를 고정해 놓은 시계가 아니기 때문입니다.

기준은 미국의 월~금 각 업무일입니다.

> 미국 동부 오전 9시부터, 같은 미국 날짜의 서부 오후 6시까지를 BURGER TIME으로 봅니다.

미국은 계절에 따라 시계를 한 시간 바꾸는 **서머타임(DST)**을 사용합니다. 앱은 Windows의 시간대 정보를 사용하므로 사용자가 한 시간씩 고칠 필요가 없습니다.

아래는 공휴일이나 DST 전환이 끼지 않은 보통의 주입니다.

| 미국 시간 모드 | 한국에서 보이는 BURGER 구간 | 주말에 이어지는 FULL 구간 |
|---|---|---|
| 서머타임(DST) | 22:00~다음 날 10:00 | 토요일 10:00~월요일 22:00 |
| 표준시간(Standard) | 23:00~다음 날 11:00 | 토요일 11:00~월요일 23:00 |

시계가 바뀌는 주말에는 연속 FULL이 59시간 또는 61시간일 수도 있습니다. 카운트다운은 실제 다음 전환 시각을 사용합니다.

### 공휴일 보정은 무엇을 바꾸나요?

기본값은 **ON**입니다. 미국 정기 연방 공휴일 11종과 대체휴일에 해당하는 업무 구간을 시간표에서 뺍니다.

예를 들어 미국 월요일이 대상 공휴일이면, 금요일 업무가 끝난 뒤의 FULL이 화요일 업무 시작까지 이어질 수 있습니다.

- 토요일 공휴일은 앞 금요일, 일요일 공휴일은 다음 월요일을 쉬는 일반적인 월~금 근무 규칙을 사용합니다.
- 한국 날짜 하루 전체를 FULL로 바꾸는 방식은 아닙니다.
- 창에 ‘주말+공휴일’ 또는 ‘공휴일’이 표시됩니다. 다음 전환 글자 위에 마우스를 올리면 반영된 공휴일 이름을 볼 수 있습니다.
- 설정을 끄면 기존의 “주말만 제외하는 시간표”로 돌아갑니다. 선택은 재시작 후에도 유지됩니다.

회사별 휴가, 주·지역 공휴일, 임시 휴무, 반일 휴무는 포함하지 않습니다. **연방 공휴일이라고 AI가 반드시 한산한 것은 아닙니다.** 자세한 범위는 [공휴일 정책 설명](HOLIDAYS_TRAY.md)에 있습니다.

## 7. 내 경험을 기록하고 통계 보기

Provider 행을 우클릭해서 하나를 고릅니다.

| 기록 | 내가 느낀 결과 |
|---|---|
| Success | 잘 끝났어요 |
| Slow | 느렸어요 |
| Error | 오류가 났어요 |
| Interrupted | 도중에 끊겼어요 |

앱은 그때의 시각, 시간표, DST, 공휴일 설정, 공식 상태와 권고를 함께 적어 둡니다. 메모는 선택 사항입니다.

메모는 저장할 때 앞뒤 공백을 정리한 뒤 최대 1,000 UTF-16 단위까지 보관합니다. 이모지·결합 문자를 중간에서 자르지 않으므로 경계에 따라 999자 등으로 저장될 수도 있습니다. **실제로 잘렸으면 ‘앞부분 N자만 저장’ 안내**를 표시하며, 1,000자 이하나 공백만 정리된 경우는 기존 ‘저장됨’ 안내를 유지합니다. 입력 중에는 잘라 버리지 않고 저장 시 한 번만 적용합니다.

공식 장애 중에도 내 작업이 성공했다면 Success로 기록하면 됩니다. 공식 정상이지만 내가 오류를 겪었다면 Error로 기록하면 됩니다. 두 정보는 서로를 덮어쓰지 않습니다.

Statistics에서는 최근 7일·30일·전체 기록을 볼 수 있습니다. Provider별, 한국 시간대별, FULL/BURGER별, 주말·공휴일별, DST/표준시간별로 나눠 봅니다.

- **n = 3:** 직접 남긴 기록이 세 개라는 뜻입니다.
- **No data:** 그 구간에는 기록이 없습니다. 성공률 0%라는 뜻이 아닙니다.
- 30개 미만이면 소표본 안내를 표시합니다. 30개가 넘었다고 자동으로 결론이 확실해지는 것은 아닙니다.

2.1.2부터 알 수 없는 Provider 이름처럼 해석할 수 없는 일부 기록은 통계에서 건너뛰고 ‘읽을 수 없는 기록 N건 제외’로 알립니다. 원본 기록을 삭제하는 것은 아니며, 모든 DB 손상을 자동으로 복구하는 기능도 아닙니다.

**이 통계는 ‘기록한 경험의 비율’이지 ‘모든 AI 작업의 오류율’이 아닙니다.** 문제를 겪을 때만 주로 기록했다면 결과도 그쪽으로 치우칠 수 있습니다.

공휴일 ON/OFF와 이전 버전의 미기록 데이터를 구분합니다. 정책 효과를 비교할 때는 정책별 FULL/BURGER 행을 보세요. 전체 행에는 서로 다른 정책의 기록이 섞일 수 있습니다.

## 8. 기록은 어디에 있나요?

이 PC의 다음 파일에 저장합니다.

~~~text
%LOCALAPPDATA%\AIBurgerClock\burgerclock.db
~~~

SQLite는 **파일 하나를 중심으로 쓰는 작은 기록장**이라고 생각하면 됩니다. 사용 중에는 옆에 임시 관리 파일이 생길 수 있습니다.

사용 기록을 외부로 전송하지 않습니다. AI 답변·프롬프트·계정 식별 정보·쿠키·인증 토큰을 저장하지 않습니다. 한도 조회의 인증은 공식 CLI에 맡기며 이 앱은 인증 파일을 직접 읽지 않습니다. CLI의 전체 출력 대신 검증한 한도 수치·기간·리셋 시각만 사용합니다. 직접 쓰는 메모에도 민감한 내용은 넣지 마세요.

백업하려면 먼저 트레이 메뉴에서 앱을 정상 종료한 뒤 기록 파일을 복사하세요. 파일을 삭제하면 새 빈 기록장이 만들어지지만, 지운 기록이 복구되는 것은 아닙니다.

2.2.0도 기록장의 구조는 schema 2입니다. 계정별 마지막 성공값은 기존 AppMetadata에 최대 두 항목으로 덮어써서 보관하며, 사용 경험·공식 상태 이력의 구조는 바꾸지 않습니다. 이전 schema 1을 처음 열 때는 같은 폴더에 자동 백업한 뒤 업그레이드합니다. 과거 기록의 판정은 새 규칙으로 덮어쓰지 않습니다.

저장 오류가 있으면 창 아래에 안내합니다. 같은 오류가 매초 새로운 ‘저장됨’ 안내를 덮어쓰지 않으며, 오류가 해소되면 남아 있는 오류 표시를 지웁니다. DB 자체를 자동으로 복구하는 기능은 아닙니다.

Provider별 공식 상태 저장 실패도 따로 기억합니다. 예를 들어 ChatGPT 상태 저장이 실패했다면, Claude 저장이 성공했다는 이유만으로 그 오류를 지우지 않습니다. 이는 로컬 저장 문제이며 해당 AI 서비스의 장애 판정과는 별개입니다.

2.2.4는 중복 Provider 입력 진단을 `%LOCALAPPDATA%\AIBurgerClock\logs\status-ticker.log`에 남깁니다. 파일당 64 KiB, 이전 파일 1개만 보관하며 정상 입력에는 로그를 만들지 않습니다. 사용자 기록 DB와는 별도이고, 로그 쓰기 실패가 화면 갱신을 멈추지 않습니다. DB 구조는 schema 2 그대로입니다.

**2.0.x로 돌아가려면 이전 DB 백업도 필요합니다.** EXE만 옛 버전으로 바꾸면 새 DB 구조를 읽지 못합니다. 현재 DB까지 보존한 뒤 복원하세요. [백업·복원 상세](HOLIDAYS_TRAY.md)

## 9. 자주 헷갈리는 점

**인터넷이 끊기면 앱도 멈추나요?**  
아니요. 시간표·카운트다운·로컬 기록은 계속 쓸 수 있습니다. 공식 상태는 UNKNOWN/STALE로 표시될 수 있습니다.

**알림은 언제 오나요?**  
시간표가 실제로 전환될 때, FULL 중 Provider 권고가 GO/HOLD/STOP 사이에서 의미 있게 바뀔 때, 공휴일 설정을 바꿀 때입니다. 같은 상태를 반복해서 알리지는 않습니다. 앱 시작 자체로 무조건 알림을 띄우지는 않습니다.

**절전 중에도 알림이 오나요?**  
절전 중에는 표시하지 못합니다. 복귀 후 현재 시간표가 이전과 달라졌으면 알립니다. 2.1.1부터 복귀 시 공식 상태의 즉시 재조회를 요청합니다. 이미 조회 중이면 그 조회가 끝난 직후 한 번 더 확인합니다. 인터넷 연결이 아직 복구되지 않았다면 조회가 실패할 수 있습니다. Windows 알림 설정에 따라 화면에 보이지 않을 수도 있습니다.

**자동 시작을 켰는데 옛 버전이 실행돼요.**  
사용할 파일을 먼저 실행한 뒤 자동 시작을 체크하세요. 현재 실행 파일의 경로로 등록합니다. 앱은 다른 경로나 Windows 차단 상태를 표시하지만, 최종 확인은 작업 관리자의 시작 앱 상태와 실제 실행 파일 위치도 함께 봐야 합니다. 레지스트리 숫자를 임의로 고치지는 마세요.

**공식 정상인데 왜 내가 쓰는 AI는 느릴까요?**  
공식 공지는 늦을 수 있고, 계정·지역·기능별 차이도 있습니다. 특히 Gemini는 Workspace 상태 페이지의 Gemini 제품 범위를 봅니다. 모든 Google AI 서비스가 포함되는 것은 아닙니다.

## 10. 직접 코드를 빌드하고 싶다면

이 부분은 개발할 때만 필요합니다. 현재 UI는 WinForms, 대상은 `net10.0-windows`, 실행 환경은 x64입니다.

Visual Studio Community 2026의 .NET 데스크톱 개발 워크로드 또는 .NET 10 SDK를 사용합니다. `AiBurgerClock.sln`을 열거나, 프로젝트 폴더의 PowerShell에서 실행하세요.

~~~powershell
.\build.ps1
~~~

빌드와 자체 검사를 합니다. 배포용 단일 EXE까지 만들려면, 실행 중인 앱을 먼저 종료한 뒤 다음 명령을 사용합니다.

~~~powershell
.\build.ps1 -Publish
~~~

- 일반 빌드: `bin\Release\net10.0-windows\win-x64` — 폴더 전체가 필요합니다.
- 배포본: `dist\win-x64\AI Burger Clock.exe` — .NET 런타임은 별도로 필요합니다.
- 직접 추가한 패키지는 `Microsoft.Data.Sqlite 10.0.12` 하나입니다. 함께 필요한 SQLite 부품은 패키지 관리자가 가져옵니다.
- 경고도 빌드 실패로 취급하고, 검사 프로그램이 실제로 끝난 결과까지 확인합니다.

개발용 검사 명령과 주의사항은 [소스 해설의 검사 안내](CODE_GUIDE.md)에 있습니다. 특히 자동 시작 설정을 바꾸는 검사는 별도 옵션이므로 일반 사용 중에는 실행할 필요가 없습니다.
